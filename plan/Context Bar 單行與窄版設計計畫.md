# Context Bar 單行與窄版設計計畫

> 目標：多個對話視窗並列時，context-bar 不再因換行變高、擋住對話。
> 已決定（2026-10-30）：
> - 寬版與窄版都一律單行。
> - 窄版採方案 D「極簡模式」，並依使用者示意圖：**不顯示小貓、進度條與 context 色條都是半高、字體變小**。
>
> 示意：`plan/Context Bar 窄視窗設計方案.html`（方案比較）、`plan/Context Bar 單行與窄版效果.html`（效果與已選定的窄版）。
> 狀態：**已實作，待實機驗收**（2026-10-30 裁決：窄版門檻 60 欄）。

---

## 一、問題與原因

四欄並列截圖（2026-10-30）中，每個視窗約 460px，`bodyColumns` 不到 60。band 從約 6 列長到約 9 列，原因有兩個：

| 位置 | 現象 | 原因 |
|---|---|---|
| context 標題列右側 | `582k of 1M · compacts at 967k 58%` 折成 2～3 行 | 這個 `Text` 沒有設 `wrap`，預設會換行 |
| 進度標題 | `ADV-CONSTRSRC-01 BLOCKED 回流（無模型啟動） N6 …` 折成 2 行 | 程式已設 `wrap="truncate-end"`，但 Desktop 實機仍換行。**原因未確認**，推測是外層 `Text` 包了多個巢狀 `Text` 時，Desktop 沒有套用截斷 |

第二點不能只靠 `wrap` 屬性，必須由 mod 自己先截好字串（見第三節）。

## 二、寬窄的分界

- **窄版**：`bodyColumns < 60`，和專案名稱縮成 6 個字元的分界相同，一個門檻管兩件事。
- **寬版**：`bodyColumns ≥ 60`。
- Terminal 與 Desktop 用同一個門檻。

## 三、單行的做法（寬版、窄版共用）

每一列都保證只有一行，做法分兩層：

1. **mod 自己先截字**：依可用寬度算出每段文字能放幾格，超過就截斷並加 `…`。中文字算 2 格（沿用 `displayWidth`、`clipWidth`）。
2. **Desktop 留安全邊界**：Desktop 的字比格子寬（P2 分隔線事件已證實），所以 Desktop 的可用寬度先乘上 `DESKTOP_TEXT_SHARE`（暫定 0.85，和分隔線同一個比例），實機驗收時再調。窄版字體變小後，同樣寬度能放更多字，比例另訂 `DESKTOP_SMALL_TEXT_SHARE`（暫定 1.0），實機再調。
3. 各列仍保留 `wrap="truncate-end"` 當第二道防線。

### 截斷優先順序

一列放不下時，先犧牲次要資訊，數字最後才截：

| 列 | 永遠保留 | 依序省略 |
|---|---|---|
| 進度標題 | 狀態記號、`0/6`、`0%` | ① stage 名稱（`N6 通知語義查核`）② run 名稱尾段加 `…` |
| 狀態列（只有寬版） | 狀態文字開頭 | 尾段加 `…`；`+N background` 改成 `+N` |
| context 標題列 | `◆ [名稱] context`、百分比徽章 | ① `· compacts at 967k` ② `▸ details` 按鈕 ③ `582k of 1M` 改成 `582k/1M` ④ 整段 token 數 |

## 五、窄版（< 60 欄）：極簡模式

依使用者示意圖：

```text
╭──────────────────────────────────────╮
│ ⏸ ADV-CONSTRSRC-01 BLOCKED 回…  0/6 0% │  ← 進度標題（小字、無 stage）
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ │  ← 半高進度條，無小貓
│ ◆ [Cuesho] context               58% │  ← context 標題（小字、只留徽章）
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ │  ← 半高 context 色條
╰──────────────────────────────────────╯
```

| 元素 | 寬版 | 窄版 |
|---|---|---|
| 字體 | 一般（`body`） | **小一級（`footnote`）**，只限 Desktop；Terminal 只有一種字級 |
| 進度標題 | 記號＋名稱＋stage＋`0/6 0%` | 記號＋名稱＋`0/6 0%`（不顯示 stage） |
| 進度條 | 小貓＋一列高色塊 | **半高細條，不畫小貓** |
| 狀態列（`waiting for you`、`⧗ Bash`） | 有 | **拿掉**；狀態改由標題前的記號與暗色表示 |
| `+N background` | 狀態列右側 | 移到進度標題右側，寫成 `+N` |
| 分隔線 | 有 | **拿掉** |
| context 標題列 | 全部 | `◆ [名稱] context` ＋徽章；token 數與 `▸ details` 不顯示 |
| context 色條 | 一列高色塊 | **半高細條** |
| 圖例（details） | 可展開 | 不提供（按鈕已隱藏；若之前展開，窄版也不畫） |

- **高度**：有進度時 2 列小字加 2 條細條，約等於現在的 3 列（現在約 9 列）；沒有進度時約 1.5 列。
- **狀態辨識**：沿用既有記號，`▶` 執行中、`⏸` 等你回應／暫停、`◌` 一段時間沒動靜、`✓` 完成、`✗` 失敗、`■` 已取消；等你回應時整列變暗。這些都已經在 P2 的標題列上，不新增記號。

### 半高細條的做法（Desktop）

色塊 `Box` 最矮就是一列，半高必須用 `Svg`。P2 的分隔線用 Svg 畫不出來，是因為 markup 本身沒有寬度，被排成 0 寬。依 API 說明，`Svg` 不給 `width` 時會「取 markup 自己的寬度，最多到所在空間的寬度」，所以：

- markup 寫成很寬的固定尺寸（例如 `width="4000" height="8"`，`viewBox="0 0 100 8"`，`preserveAspectRatio="none"`），讓它被所在空間的寬度限住，剛好撐滿一列。
- `Svg` 元件只給 `height={8}`（CSS px），不給 `width`，高度就固定是 8px，不會跟著比例縮放。
- 進度條在一張 Svg 裡畫三段：已完成（主色）、buffer（淡色 `#EDC3AE`）、其餘（灰）。context 色條同樣一張 Svg，依各類別比例畫色段，壓縮門檻位置畫一條細刻度。
- 顏色：Svg 裡不能用主題色名稱（例如 `claude`、`subtle`），要換成 hex。由 mod 內建一組對照表，淺色、深色主題各一組，依目前主題挑選。

**Terminal**：沒有 Svg，兩條仍是一列高的色塊（Terminal 一格就是一列，本來就最矮），也不畫小貓。

**保險**：細條是本次最大的風險。實機驗收若 Svg 仍畫不出來或寬度不對，Desktop 窄版退回「一列高色塊、不畫小貓」，其餘窄版規則不變。程式裡把細條做成可單獨關閉的一段，退回時只改一處。

## 六、檔案變動

| 檔案 | 變動 |
|---|---|
| `hooks/layout.ts`（新） | 寬窄判斷、Desktop 安全邊界、各列「依優先順序省略」的字串組裝；純函式，方便測試 |

| `hooks/register.tsx` | context 標題列改用預先截好的摘要；窄版拿掉分隔線、`▸ details`、圖例，色條改畫細條、文字用小字 |
| `hooks/project/name.ts` | 窄版門檻改從 `layout.ts` 取，兩處共用同一個常數 |
| 測試、`scripts/mutation.mjs` | 見下節 |

`COMPACT_COLUMNS = 80`（`+N background` 縮成 `+N` 的門檻）保留不動：60～79 欄是寬版但仍用 `+N`。

## 七、測試計畫

| 類別 | 項目 |
|---|---|
| 單行 | 寬版在 60、80、120、160 欄，窄版在 40、50、59 欄：每列預先組好的字串寬度都不超過可用寬度（Desktop 乘上安全邊界） |
| 省略順序 | context 標題列依 compacts at → details → 縮寫 token → 拿掉 token 的順序省略；徽章永遠都在；進度標題先丟 stage 再截名稱，`0/6 0%` 永遠都在 |
| 窄版結構 | 無小貓、無狀態列、無分隔線、無 details 按鈕；文字為 `footnote` 字級 |
| 細條 | Desktop 窄版：兩條都是 `Svg`、`height` 為 8、沒有 `width`；markup 有寬度、`preserveAspectRatio="none"`；三段比例與已完成、buffer 一致；只用 hex 色 |
| Terminal 窄版 | 不輸出 Svg，兩條是一列高色塊；不畫小貓 |
| 寬版不變 | 60 欄以上的結構與 P2 相同：小貓、狀態列、分隔線、details 都在（既有 snapshot 測試全過） |
| 中文 | 中文 run 名稱以 2 格計算，截斷不會切半個字 |
| 邊界 | 59 欄為窄版、60 欄為寬版；專案名稱的 6／8 字元門檻與 band 的寬窄同步 |

Mutation 新增三個：「窄版仍畫狀態列」、「context 摘要不截斷」、「細條的 Svg 拿掉 markup 寬度」，測試都必須失敗。`claude plugin validate` 必須通過。

## 八、驗收（實機）

1. **先驗細條**：四欄並列時，兩條細條都撐滿整列、高度約半列；淺色與深色主題顏色正確。不行就照第五節的保險退回。
2. 四欄並列（每欄約 460px）：band 沒有任何折行，小字可讀，沒有小貓。
3. 兩欄並列（每欄約 60～80 欄）：寬版外觀，每列單行；長 run 名稱與 token 摘要依序省略，徽章與 `0/6 0%` 完整。
4. 單一視窗全寬：與 P2 凍結時的截圖一致。
5. 拖動視窗寬度跨過 60 欄：寬窄切換正確，沒有殘影或閃爍。
6. Terminal 50 與 80 欄截圖：同樣不折行。
7. 確認 Desktop 安全邊界（0.85、小字 1.0）是否需要調整。

## 九、凍結範圍說明

本計畫解凍 P2 的「各列換行行為」與「窄版排版」。寬版的分隔線、進度條色彩、小貓、context 色條外觀維持凍結；P3 的 committed = 0% 淺色 buffer 觀察項仍不在本次範圍。

## 十、實作紀錄（2026-10-30）

- **新模組**：
  - `hooks/layout.ts`：寬窄判斷（`NARROW_COLUMNS = 60`）、可用寬度、依序省略的標題與 context 摘要。
  - `hooks/thinbar.ts`：半高細條的 Svg（markup 寬 4000、`preserveAspectRatio="none"`、元件只給 `height=8`），以及主題色到 hex 的淺色／深色對照；`THIN_BARS` 一處即可關閉細條。
  - `hooks/text.ts`：從 `project/name.ts` 抽出的字寬計算，供兩邊共用（避免互相 import）。
- **主題**：session 開始時以 `$.config.list()` 讀 `theme`，名稱含 `light` 用淺色對照，其餘用深色。
