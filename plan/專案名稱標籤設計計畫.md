# 專案名稱標籤設計計畫（方案 A）

> 目標：在 context-bar 的 context 標題列帶出專案名稱，讓不同專案的視窗一眼分得出來。
> 已決定：採用方案 A（見 `plan/專案識別重新設計方案.html`），名稱可自訂，也可自動縮寫，外框用 `[ ]`。
> 狀態：**已實作，待實機驗收**（2026-10-27 裁決：預設縮寫方式、藍底白字、名稱最多 8 個字元，加上 `[ ]` 整塊最多 10 格）。

---

## 一、外觀

只改 context 標題列一處，其他（進度卡片、分隔線、小貓、context 色條、徽章）維持 P2 凍結狀態。

```text
現在： ◆ context  ▸ details                 806k of 1M · compacts at 967k  81%
改後： ◆ [SmartCA1] context  ▸ details      806k of 1M · compacts at 967k  81%
         └ 藍底白字 ┘
```

| 部分 | 樣式 | 說明 |
|---|---|---|
| `◆` | 維持 `claude` 色 | 不換色，和進度卡片的 `▶` 保持同一套記號 |
| `[名稱]` | 藍底（`#2F6FB0`）白字，粗體 | 和右側的百分比徽章同一種「底色塊」語彙；所有專案同色，靠文字區分 |
| `context` | 維持粗體 | 不變 |

- 原本方案 A 的 `·` 拿掉，由 `[ ]` 取代分隔作用。
- 「尚未量測」那一列（`◆ context waiting for first measurement…`）同樣加上 `[名稱]`。

## 二、名稱來源（優先順序）

1. **自訂名稱**：用指令設定，存在 context-bar 自己的 `$.store`，以專案鍵為索引，跨 session 保留。
2. **自動縮寫**：沒有自訂時，由專案資料夾名稱產生。
3. **都拿不到**（例如讀不到工作目錄）：不顯示 `[ ]`，回到現在的 `◆ context`。

### 專案鍵

- 取 `$.session.root()`（session 的專案根，`/cd` 或 worktree 移動會跟著變）；拿不到時用 `session.start` 事件的 `cwd`。`/clear` 不會觸發 `session.start`，沿用上一次記住的值。
- 正規化：統一正斜線、去掉結尾斜線；Windows 路徑不分大小寫。
- 從該位置往上找含 `.git` 的目錄當專案根，子資料夾算同一個專案；找不到就用該位置本身。

## 三、自動縮寫規則

1. **切字**：資料夾名稱依 `-`、`_`、`.`、空白，以及大小寫交界、字母與數字交界切開。
   - `SmartCameraApp1` → `Smart` `Camera` `App` `1`
   - `mcp-ticket-platform` → `mcp` `ticket` `platform`
2. **夠短就不縮**：顯示寬度 ≤ 8（中日韓字元算 2 格）時直接用全名。
   - `projman` → `projman`
3. **太長才縮**：保留第一個字（最多 6 格，且總長不超過 8），後面每個字取第一個字母並轉大寫，數字整段保留。
   - `claude-mods` → `claudeM`
   - `SmartCameraApp1` → `SmartCA1`
   - `mcp-ticket-platform` → `mcpTP`
   - `AndroidStudioProjects` → `AndroiSP`（第一個字 `Android` 超過 6 格，截成 `Androi`）
4. **撞名時加編號**：mod 會記住已見過的專案與它們的名稱。新專案的縮寫和別的專案（含自訂名稱）相同時，在後面加 `2`、`3`…，必要時先截短，總長仍不超過 8（`SmartCA1` → `SmartCA2`）。
   - 已經顯示過的名稱不會因為之後出現新專案而改變，避免你認熟的名字突然變了。

> 已裁決：採「首字 + 字首」。

## 四、自訂指令

新增 `/project-name`（放在 context-bar 裡，和 `/progress` 並列）：

| 指令 | 作用 |
|---|---|
| `/project-name` | 顯示目前的專案鍵、顯示名稱、來源（自訂／自動）與自動縮寫的結果 |
| `/project-name <文字>` | 設定這個專案的名稱，例如 `/project-name Cam` |
| `/project-name reset` | 清除自訂，回到自動縮寫 |
| `/project-name off` | 這個專案不顯示 `[ ]` |
| `/project-name on` | 恢復顯示 |
| `/project-name reload` | 重新讀取名稱（其他 session 改過名稱時用） |

- 自訂名稱最多 8 格，超過的部分直接截掉並在回覆中告知；前後空白會去掉，`[`、`]` 不允許出現在名稱裡。
- 設定後立即重繪，不用 `/reload-plugins`。

## 五、窄欄處理

| 欄寬（`bodyColumns`） | 名稱最大寬度 |
|---|---|
| ≥ 60 | 名稱 8 格（含 `[ ]` 共 10 格） |
| < 60 | 名稱 6 格（含 `[ ]` 共 8 格） |

超過就截斷。右側的 token 摘要照舊由既有排版處理，不改它的規則。

## 十二、修正：同一專案出現兩個名稱（2026-10-28）

- **現象**：同一專案的幾個 session 中，有一個顯示自動縮寫，其他顯示自訂名稱；在那個 session 執行 `reset` 後仍不一致。
- **原因 1：名稱只在 session 開始時讀一次。** 在 A session 自訂後，已開著的 B session 不知道。在 B 執行 `reset` 會清掉整個專案的自訂名稱。
- **原因 2：專案鍵跟著工作資料夾走。** session 移到子資料夾（例如 `context-bar/`）就被當成另一個專案。
- **修正**：
  - 專案鍵改回計畫原意：從 session 的資料夾往上找 `.git`，找到的 repo 根才是專案；子資料夾都算同一個專案。
  - 新增 `/project-name reload`：手動重新讀取名稱。依裁決不做自動輪詢（每 10 秒太頻繁），發現名稱不一致時自行執行。
- **結果**：測試 85 pass / 0 fail（新增 2 個）；mutation 8/8 killed；`claude plugin validate` 通過。
